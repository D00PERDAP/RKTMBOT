# Диагностика замен и безопасное обновление

## Причины неисправностей

Проверена ветка main, исходный коммит 9b7660cd099d1751f7756a933a723ec4f8a7c55d.

- Telegram хранит выбор в users; bot_roles и bot_accounts обслуживают роль и регистрацию. Источник raspisan означает группу, Praspisan — преподавателя. MAX сохранял выбор только в max_profiles, поэтому единый список подписок не содержал MAX-профилей. Добавлена совместимая миграция INSERT OR IGNORE в users, сохранение выбора в обе таблицы и /notify, /mute.
- Оба раздела «Мои замены» явно отклоняли Praspisan. Теперь общая функция фильтрует студентов по коду группы, преподавателей по фамилии и инициалам в обеих колонках: исходный и заменяющий преподаватель.
- group_key терял суффикс «к». Теперь ОЛ-29 и ОЛ-29к различаются; короткие и полные каталожные коды, пробелы и разные тире нормализуются.
- Кнопки дат вычислялись от момента нажатия, показывали неопубликованные даты и могли изменить смысл после полуночи. Теперь payload содержит ISO-дату из сохранённых публикаций.
- Уведомления запускались только для changed, возвращённого refresh. После ошибки отправки PDF уже считался обработанным, повторов не было. Теперь каждый цикл сверяет актуальный адресный текст с успешной доставкой в SQLite; повторяет неудачные отправки даже при ошибке получения страницы.
- MAX добавлялся вторым списком в обход notifications, только для студентов. Теперь используется один список users с явным opt-out, включая преподавателей. Существующая выключенная подписка при миграции и смене выбора сохраняется.
- В Telegram отсутствовал /notify, а /mute перехватывал общий обработчик router. Команды зарегистрированы до него.
- Длинные сообщения Telegram обрезались до 3900 символов. Теперь все части показываются; уведомления сохраняют подтверждение каждой части, чтобы не повторять уже отправленные части после частичной ошибки.
- MAX-строки содержали литеральные обратные слеши перед n. Исправлены переносы строк и разбиение сообщений.
- Монитор запускался только при наличии Telegram-токена. Теперь поддерживается MAX-only, а файловая блокировка возле DATABASE_PATH исключает конкурирующие мониторы на одном VPS. При совместном запуске двух ботов монитор принадлежит FastAPI; MAX-процесс занимается получением команд.

## Что проверено

01.11.2026 напрямую получена официальная страница расписания и найден PDF на 02.11.26. Скачаны оригинальные PDF за 28.10.26 (18 строк) и 02.11.26 (14 строк), сохранены как offline fixtures с ожидаемыми строками. Проверены объединённые номера уроков, переносы занятий, кабинеты текстом и группы с суффиксом. Не распознанный/пустой PDF сохраняет прежние данные и не считается успешно обработанным. SHA-256 вычисляется по содержимому, поэтому изменение файла по прежнему URL обнаруживается. Новый URL исправленной публикации для той же даты вытесняет строки отсутствующей на странице старой версии; записи документов сохраняются.

Старый ключ (URL, группа, урок) терял вторую подгруппу на том же уроке. Добавлена таблица substitution_rows_v2 с полным ключом строки и одноразовым копированием старых замен; старые таблицы не удаляются.

Локально: Python 3.10, установка зависимостей, pip check, unittest. CI проверяет Ubuntu 22.04 с Python 3.10 и 3.12. Тесты используют временные базы, реальные PDF и подменённый транспорт Telegram/MAX; реальным пользователям сообщения не отправлялись. Состав зависимостей зафиксирован в requirements.lock.txt, tzdata добавлен для Windows и минимальных образов.

## Ограничения и проверка перед обновлением

Доступа к фактическому VPS, его systemd units, рабочей базе и токенам в этой задаче нет. Совместимость конкретного сервера и реальную доставку нужно подтвердить на тестовых аккаунтах. Слияние и развёртывание не выполнялись. Старый PR #5 не изменялся; при его дальнейшем слиянии нужно разрешить возможные конфликты app.py.

MAX сохраняет существующий long polling. Не запускайте его одновременно с MAX webhook subscription. Официальная документация: https://dev.max.ru/docs-api и https://dev.max.ru/docs-api/methods/POST/messages . Используется platform-api2.max.ru и Authorization header. Если на VPS ошибка TLS, установите проверенный доверенный сертификат по инструкции MAX и задайте SSL_CERT_FILE для httpx; отключать проверку TLS нельзя.

Гарантия доставки — повторяемая доставка с сохранением подтверждений, а не абсолютное exactly-once: при аварии между приёмом сообщения платформой и записью SQLite или при неоднозначном сетевом таймауте возможен повтор. Блокировка рассчитана на один VPS с локальной SQLite, не на несколько серверов/NFS. Неизвестные форматы и сканированные PDF требуют отдельного адаптера; текущий парсер не выполняет OCR и не стирает данные при отсутствии распознанных строк. Если официальный PDF вообще не указывает инициалы, сопоставление возможно только по фамилии; однофамильцев невозможно достоверно различить без исходных данных.

Регистрация выбирает преподавательское расписание самостоятельно, роль не является проверкой личности. Старый парольный сценарий и новые onboarding-сценарии сосуществуют. Это не меняет права администратора; учётные записи и хеши паролей сохранены. Основной HTML-парсер расписания и генерация карточек не изменены.

## Порядок обновления Ubuntu

1. Дождаться проверки PR и зелёного CI. Уточнить текущий каталог приложения, имена systemd units, версию Python (3.10–3.12) и абсолютный DATABASE_PATH. Оба процесса должны использовать один и тот же DATABASE_PATH, каталог должен быть доступен сервисному пользователю на запись (включая файл блокировки). Не переносить базу в новый пустой каталог.
2. Сохранить текущий SHA (`git rev-parse HEAD`), конфигурацию systemd и защищённую копию .env. Сделать согласованную резервную копию SQLite через SQLite backup API, а не копированием работающего файла. Не запускать scripts/reset_users.py.

```bash
# Из текущего каталога приложения. Пути backup выбрать вне git и закрыть права.
umask 077
.venv/bin/python - <<'PY'
from dotenv import load_dotenv
load_dotenv()
from features import DB_PATH
import sqlite3
from datetime import datetime
backup = DB_PATH.with_name(DB_PATH.name + '.backup-' + datetime.now().strftime('%Y%m%d-%H%M%S'))
with sqlite3.connect(DB_PATH) as src, sqlite3.connect(backup) as dst:
    src.backup(dst)
print('SQLite backup completed')
PY
```

3. После одобрения получить проверенный SHA PR через `git fetch origin`, убедиться в отсутствии локальных изменений и переключиться на этот SHA. Сохранить .env и абсолютный DATABASE_PATH. Не применять git clean/reset и не удалять data/.
4. Подготовить новое окружение, сохраняя прежнее для отката:

```bash
python3 -m venv .venv-next
.venv-next/bin/python -m pip install -r requirements.lock.txt
.venv-next/bin/python -m pip check
.venv-next/bin/python -m unittest discover -s tests
.venv-next/bin/python -m playwright install --with-deps chromium
```

5. Остановить текущие службы Telegram/FastAPI и MAX. В systemd поменять ExecStart на .venv-next, сохранив WorkingDirectory, EnvironmentFile и DATABASE_PATH. Запустить сначала MAX один раз для миграции профилей (при наличии BOT_TOKEN его монитор отключён), затем FastAPI с одним worker. Если используется только MAX, достаточно max_bot.py без BOT_TOKEN. Миграции добавляют таблицы строк v2, отметку одноразового переноса и подтверждения частей, существующие пользователи, настройки и секреты не удаляются.
6. Проверить `/health`, журналы обеих служб, отсутствие исключений PDF/SQLite/TLS и сообщение об обнаружении публикаций. Проверить существующего студента и преподавателя: /start, расписание, «Мои замены», «Замены на день», возврат в меню, /mute, /notify. На тестовом окружении воспроизвести публикацию, повторный цикл без изменений, изменение кабинета по тому же URL, временную ошибку отправки и перезапуск. Убедиться, что отключённый аккаунт сообщений не получает. На первом старте активные подписчики получат текущие/будущие замены, если для них ещё нет подтверждения доставки.
7. При ошибке остановить обе службы, вернуть прежний SHA и ExecStart прежнего окружения, запустить службы. Добавленные таблицы совместимы со старым кодом; восстанавливать базу обычно не требуется. Резервную копию восстанавливать только отдельно согласованно: это отменит новые регистрации и настройки, сделанные после backup.
